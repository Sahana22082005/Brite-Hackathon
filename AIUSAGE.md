# AI Usage Disclosure

## 1. Purpose

Generative AI tools were used during the Brite Hackathon project as an **assistive tool** for development, documentation, code review, and analytical reasoning.

AI was not treated as the source of truth for the dataset or the final findings.

All important analytical decisions were checked against the actual data and implemented in the analysis code.

---

# 2. How AI Was Used

AI assistance was used for the following activities:

### Code Assistance

AI was used to help:

* Draft Python/Pandas code
* Suggest data-cleaning approaches
* Identify possible validation checks
* Structure analytical workflows
* Explain Python and Pandas operations
* Suggest ways to calculate closure durations
* Organize exploratory analysis

The generated code was reviewed and tested before being used.

---

## 2.1 Data Quality Analysis

AI was used to suggest checks for:

* Missing values
* Duplicate records
* Duplicate case IDs
* Invalid dates
* Negative closure durations
* Potential outliers
* Category inconsistencies
* Priority inconsistencies

The actual results were calculated from the supplied datasets rather than generated by AI.

---

## 2.2 Reconciliation Analysis

AI assistance was used to design a reconciliation approach for the supplementary export.

This included:

* Mapping different field names
* Normalizing case IDs
* Identifying overlapping records
* Comparing fields between exports
* Separating overlapping and supplementary-only records
* Documenting disagreements

The final reconciliation results were produced by executing code against the actual datasets.

---

## 2.3 Analytical Reasoning

AI was used to help structure the analysis around the three operational questions:

1. Whether closure times increased.
2. What operational factors were associated with the change.
3. Whether the 2024 triage process could be evaluated.

AI was also used to identify potential limitations and distinguish between:

* Descriptive evidence
* Association
* Causal claims

---

# 3. What AI Did Not Determine

AI was **not used to invent or estimate dataset values**.

The following were calculated directly from the supplied data:

* Number of records
* Missing-value counts
* Duplicate counts
* Closure durations
* Yearly closure-time statistics
* District-level statistics
* Priority-level statistics
* Reconciliation results
* Percentage changes

AI did not independently determine the numerical results.

---

# 4. Human Verification

All important AI-assisted outputs were reviewed by the project team.

The team verified:

* Data-cleaning decisions
* Transformation logic
* Inclusion and exclusion criteria
* Reconciliation rules
* Statistical calculations
* Operational conclusions
* Limitations
* Recommendations

Where the available data did not support a conclusion, the analysis explicitly reported that limitation.

---

# 5. Avoiding AI Hallucination

AI-generated suggestions were not accepted without verification.

For example, the AI was not allowed to assume:

* That a missing priority meant low priority.
* That a newer export was automatically more accurate.
* That a long-running case was an error.
* That a district caused an increase in closure time.
* That the 2024 triage intervention caused a change in high-priority closure times.

Such conclusions would require evidence from the dataset.

---

# 6. Causal Interpretation

Particular care was taken to avoid unsupported causal claims.

For example:

```text
Observed:
Weybridge closure times increased.

Not established:
Weybridge caused the overall increase.
```

Similarly:

```text
Observed:
High-priority closure time changed between 2024 and 2025.

Not established:
The 2024 triage process caused that change.
```

The absence of a reliable intervention indicator means that the triage question cannot be answered causally using the available data.

---

# 7. AI and Sensitive Data

The project follows responsible data-handling practices.

Raw case-management data should not be unnecessarily uploaded to external AI systems, particularly where it may contain confidential or personally identifiable information.

AI assistance should focus on:

* Code structure
* Methodology
* Documentation
* General analytical reasoning

rather than exposing sensitive case-level information unnecessarily.

---

# 8. Reproducibility

The final numerical findings are reproducible from the analysis code and supplied datasets.

The project maintains:

* Raw data separately from cleaned data
* Documented cleaning decisions
* Reconciliation rules
* Analysis code
* Explicit exclusion criteria
* Documented limitations

AI assistance does not replace the underlying computational evidence.

---

# 9. Summary

AI was used as a **development and analytical assistant**, not as an autonomous decision-maker.

The final conclusions were based on calculations performed against the supplied datasets and were reviewed for consistency with the documented methodology.

The project deliberately prioritizes:

> **Data → Evidence → Interpretation → Decision**

rather than allowing AI-generated assumptions to determine the outcome.

The most important example is Question 3: although AI could suggest possible ways to evaluate the 2024 triage process, the final analysis correctly concludes that the available data **cannot reliably establish its causal effect**.
